# R0 TMAP 도보 경로 타당성 기록

| 항목 | 내용 |
| --- | --- |
| 기준일 | 2026-08-27 |
| PRD2 기능 | F5 앱 내부 실제 도보 이동동선 |
| 현재 판정 | 기술 통합 진행 가능 — REST·Vector JS 인증과 대표 10구간 응답 성공, 출입구·보행로 수동 검수는 대기 |
| 다음 구현 스프린트 | R7, 단 F15 시간표 계약과 본 문서의 실호출 게이트 통과 필요 |

## 1. 공식 확인 결과

- TMAP API는 Vector Map SDK for JavaScript와 보행자 경로안내 상품을 제공한다.
- 공식 약관의 현재 무료 제공 한도는 경로안내 일 1,000건, 지도보기 일 100,000건이다.
- TMAP Open API로 얻은 데이터는 저장 후 24시간 이상 사용할 수 없다.
- 같은 서비스를 위해 여러 프로젝트를 만들어 무료 한도를 우회하면 서비스가 중지될 수 있다.
- 제품은 TMAP 지도와 TMAP 보행 경로를 함께 쓰는 것으로 설계한다. 다른 공급자 바탕지도와의 결합은 허용을 확인하기 전 적용하지 않는다.

공식 근거:

- [TMAP API 약관](https://tmapapi.tmapmobility.com/terms.html)
- [TMAP API 가이드](https://tmapapi.tmapmobility.com/)
- [SK open API TMAP 상품](https://openapi.sk.com/products/detail?menuSeq=432&svcSeq=4)

## 2. 로컬 환경 확인

환경 변수 이름만 점검했으며 값은 출력하지 않았다.

| 항목 | 결과 |
| --- | --- |
| TMAP Vector Map 브라우저 키 | `NEXT_PUBLIC_TMAP_MAP_KEY`를 Vercel에 설정하고 프로덕션 Vector 지도 표시 확인 |
| TMAP REST 보행 경로 키 | `TMAP_API_KEY` 있음, 40자 ASCII 토큰·공백 없음 |
| REST 보행 경로 인증 | 성공 — form body의 `appKey`로 대표 10구간 모두 HTTP 200·LineString 확인 |
| Vector JS 인증 | 성공 — HTTP 200, JavaScript 응답 확인 |
| Kakao 지오코딩 키 | 과거 좌표 생성 provenance에만 존재, 사용자 런타임에서는 미사용 |
| NAVER 지도·앱 연결 | 사용자 런타임에서 제거 |
| 현재 앱 내부 실제 보행 경로 | TMAP 서버 REST·경로선·거리·시간 구현 |
| 현재 실패 상태 | 다른 지도 공급자 없이 공급자 중립 건물 순서·직선거리 `추정`만 표시 |

키 값은 출력하거나 로그·문서에 저장하지 않았다. 2026-08-27에 앱과 같은 `.env.local` 로딩 방식으로 확인한 결과,
이 프로젝트 키는 `appKey`를 HTTP 헤더에 넣으면 403 `INVALID_API_KEY`를 반환했지만 URL query 또는 form body에
넣으면 HTTP 200으로 실제 보행 경로를 반환했다. URL query는 프록시·접근 로그에 키가 남을 수 있으므로 검증기와
향후 서버 연동은 `application/x-www-form-urlencoded` form body 방식만 사용한다.

제품 책임자가 대시보드의 허용 IP와 상품 상태를 조정한 뒤 대표 10개 구간을 재검증했고, 모두 HTTP 200과 하나 이상의
GeoJSON LineString을 반환했다. Vector JS 로더도 같은 App Key로 HTTP 200 JavaScript 응답을 반환했다. API 지원과
인증은 통과했지만, 이 결과만으로 건물 중심 좌표가 올바른 출입구·보행로에 스냅됐다고 판정하지는 않는다.

재검증 명령은 `pnpm tmap:smoke`이며 첫 대표 구간만 호출한다. 인증 통과 후 `pnpm tmap:verify`로 10개 구간을
검증한다. 스크립트는 키와 경로 geometry를 출력·저장하지 않고, 401/403이면 첫 호출에서 중단한다.

## 5. go/no-go 기준

### Go

- Vector Map과 보행 경로 상품 키가 발급됨
- 대표 10개 중 최소 8개가 합리적인 출입구·보행로에 스냅됨
- 자동차 전용 경로가 도보 결과로 섞이지 않음
- 서버 프록시에서 건물 ID 허용 목록, 캠퍼스 범위, rate limit, timeout을 적용할 수 있음
- geometry 영구 저장 없이 24시간 이하 캐시로 예상 사용량을 감당할 수 있음

### 대체 공급자 검토

- 지원되지 않는 캠퍼스가 핵심 사용자 범위에 포함됨
- 대표 구간의 20%를 넘는 경로가 자동차 도로·잘못된 출입구에 스냅됨
- 약관상 앱 내부 표시 또는 필요한 캐시 전략을 사용할 수 없음

### 보류

- appKey·상품 승인이 없음
- 공식 또는 직접 검수한 출입구 좌표가 없음
- 일 사용량 추정이 무료 한도를 넘지만 비용 승인이 없음

## 6. 현재 결정

현재 결정은 **기술 통합 및 제한적 운영 진행**이다. App Key, 보행 REST 지원, Vector JS 로더, 전주캠퍼스 대표
10구간의 구조화 응답과 프로덕션 지도 표시는 통과했다. 공식 출입구와 실제 보행로 수동 검수 전까지는 서버
allowlist에 등록되고 자동 검증을 통과한 좌표만 허용하고, kill switch와 공급자 중립 실패 상태를 유지한다.

다음 순서로 재개한다.

1. 대시보드의 전체 IP 허용은 진단 후 최소 허용 범위로 되돌리고 서버의 실제 egress 정책을 기록한다.
2. 브라우저용 `NEXT_PUBLIC_TMAP_MAP_KEY`와 서버 REST 키의 분리는 완료했다. 대시보드의 허용 도메인·서버 egress
   제한을 운영 환경에 맞게 최소화하고 변경 이력을 남긴다.
3. 구현된 건물 ID allowlist, 전주캠퍼스 범위, timeout, 요청 제한, 23시간 캐시를 회귀 검증한다.
4. 시설 좌표 검수자가 위 대표 구간의 실제 출입구와 보행로 스냅을 확인한다.
5. 수동 검수 결과가 8/10 이상이면 운영 범위를 확정하고, 미달이면 kill switch 또는 좌표 보정을 적용한다.

## 7. 2026-08-27 선구현 결과

R0 실호출 스파이크를 제품 코드까지 연결했다. 다만 아래의 기술 구현 완료는 출입구·보행로 품질 검수를 대신하지 않으며,
F5의 최종 PRD2 완료 판정은 R7에서 F15 확정 시간표 계약과 함께 수행한다.

- `POST /api/tmap/walking`은 클라이언트 좌표가 아니라 서버에 등록된 전주캠퍼스 건물 키만 받는다.
- `needsReview` 좌표, 미등록 건물, 동일 위치, 임의 필드·좌표는 TMAP 호출 전에 차단한다.
- App Key는 URL·브라우저·응답에 넣지 않고 서버의 form body로만 전달한다.
- 구간은 병렬 호출하며 성공 구간은 유지하고 실패 구간만 코드로 반환한다. 공급자 원문 오류는 노출하지 않는다.
- 성공 응답은 프로세스 메모리에 최대 256개, 23시간 캐시하고 동일 동시 요청을 합친다.
- 공급자 timeout은 8초, 사용자별 API 요청은 분당 10회로 제한하며 브라우저 응답은 `no-store`다.
- 요일 전환 시 이전 요청을 취소하고, 각 성공 구간의 실제 시간을 지도와 목록에 표시한다. 하루 총합은 노출하지 않으며 실패 구간은 다른 공급자 호출 없이 추정값으로 분리한다.
- TMAP 경로 geometry는 다른 공급자 지도에 전달하지 않는다. 공개 지도 키가 없으면 공급자 중립 경로 윤곽만 표시한다.
- 수업이 하나인 날은 경로 REST API를 호출하지 않고 TMAP 지도에 건물 핀과 수업 정보를 표시한다.
- 실제 경로의 거리 가중 중간 지점에 `도보 n분`을 표시한다.

실제 앱 API 검증에서는 첫 요청이 HTTP 200·TMAP 실측 1,251m/1,077초·LineString 14개로 성공했고,
동일한 두 번째 요청은 `cache: hit`로 응답했다. 임의 좌표와 잘못된 Content-Type은 HTTP 400,
미등록 건물은 외부 호출 없이 `UNKNOWN_BUILDING`으로 반환됐다. `pnpm tmap:verify`의 대표 10구간도 모두 HTTP 200과
LineString을 확인했다.

환경 변수 정책:

- `TMAP_API_KEY`: 서버 REST 호출용 필수 키. 클라이언트 번들에 포함하지 않는다.
- `NEXT_PUBLIC_TMAP_MAP_KEY`: TMAP Vector JS 바탕지도용 공개 키. 프로덕션에 설정했으며 대시보드에서 허용 도메인을 제한한다.
- `TMAP_ROUTE_ENABLED=false`: 장애·쿼터·검수 이슈 시 서버 경로 기능을 즉시 중단하는 kill switch다.

남은 출시 게이트는 대표 10구간의 실제 출입구·보행로 수동 검수, 전체 IP·공개 지도 허용 범위 최소화,
일일 쿼터 운영 계측이다.
