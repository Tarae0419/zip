## 2. 제품 비전

수강길잡이 V2는 단순한 과목 탐색 서비스를 넘어, 학생이 **수강 계획 → 역량 개발 → 포트폴리오 → 취업 준비**를 하나의 흐름에서 관리하도록 돕는 AI 기반 대학생활·진로 설계 플랫폼을 지향한다.

학생은 학과, 학년, 이수 과목, 관심 분야와 가능한 시간대를 바탕으로 계획을 세우고, AI 추천의 근거와 공식 출처를 직접 확인·수정할 수 있어야 한다.

## 3. 문제 정의

1. 과목별 수강 규모와 학기별 변화가 흩어져 있어 과목 수요를 파악하기 어렵다.
2. 학과 교육과정과 진로 준비 활동이 연결되어 있지 않아 학생이 학년별 계획을 스스로 조합해야 한다.
3. 시간표, 수업 내용, 학습 자료, 면접 준비가 각각 분리되어 있다.
4. 자격증·취업·학교 및 학과 공지가 여러 채널에 흩어져 있고 관심 공지를 놓치기 쉽다.
5. AI 추천의 근거와 데이터 최신성이 보이지 않으면 커리큘럼 추천을 신뢰하기 어렵다.
6. 선수과목과 이수체계도를 고려하지 않은 추천은 실제 수강 계획으로 사용할 수 없다.

## 4. 목표와 비목표

### 4.1 제품 목표

- 학과별 공식 이수체계와 선수과목을 반영한 실행 가능한 커리큘럼을 제공한다.
- 사용자의 학년·관심 분야·이수 내역을 과목, 활동, 자격증, 포트폴리오 계획으로 연결한다.
- 시간표를 중심으로 수업 요약, 학습 계획, 면접 질문을 연결한다.
- 학교·학과·취업 공지를 통합하고 관심 키워드 기반 알림을 제공한다.
- 모든 AI 추천에서 근거, 출처, 최신성, 불확실성을 확인할 수 있게 한다.

### 4.2 성공 지표

| 지표 | 초기 목표 |
| --- | --- |
| AI 커리큘럼 생성 완료율 | 시작 사용자 중 70% 이상 |
| 추천 커리큘럼 사용자 수정률 | 측정 후 기준 수립; 수정은 실패가 아닌 참여 지표로 해석 |
| 추천 만족도 | 5점 만점 평균 4.0 이상 |
| 공식 데이터 출처 표시율 | 추천에 사용한 필수 데이터 100% |
| 공지 수집 최신성 | 게시 후 24시간 이내 반영 95% 이상 |
| 키워드 알림 유효 클릭률 | 20% 이상 |
| 잘못된 선수과목 추천 | 검증 표본 기준 0건 목표 |

수치는 베타 운영 후 조정한다. 만족도는 전체 점수뿐 아니라 정확성, 유용성, 설명 가능성, 최신성을 분리해 측정한다.

### 4.3 비목표

- 학교의 공식 수강신청 시스템을 대체하거나 자동으로 수강신청하지 않는다.
- 자격증 취득, 취업 합격, 졸업 가능 여부를 보장하지 않는다.
- 출처와 이용 권한이 확인되지 않은 자기소개서 원문을 수집·재배포하지 않는다.
- 교재 원문이나 유료 학습자료를 무단 제공하지 않는다.
- AI 답변만으로 졸업 요건 충족 여부를 확정하지 않는다.

## 5. 주요 사용자

- **저학년 탐색형:** 전공과 진로를 탐색하며 학년별 활동과 기초 과목을 알고 싶은 학생
- **고학년 취업 준비형:** 이수 과목을 포트폴리오와 면접 준비로 연결하고 싶은 학생
- **시간표 최적화형:** 오전·오후·공강 선호를 반영해 현실적인 시간표를 만들고 싶은 학생
- **학과 운영자:** 이수체계, 선수과목, 추천 근거와 공지 데이터의 정확성을 관리하는 담당자

## 6. 핵심 사용자 여정

1. 사용자가 학과, 학번 또는 적용 교육과정 연도, 현재 학년, 이수 과목, 관심 분야를 입력한다.
2. 시스템이 공식 이수체계도와 선수과목을 적용해 남은 필수 요건을 계산한다.
3. AI가 학기별 과목과 학년별 비교과 활동을 포함한 커리큘럼 초안을 생성한다.
4. 사용자는 추천 이유와 출처를 확인하고 과목·활동을 추가, 제외, 이동한다.
5. 커리큘럼을 포트폴리오 계획으로 전환하고 결과물과 활동 기록을 누적한다.
6. 시간표를 생성해 수업별 요약, 학습 계획, 예상 면접 질문을 관리한다.
7. 관심 키워드에 맞는 학교·학과·자격증·취업 공지를 알림으로 받는다.

## 7. 기능 요구사항

### F6. 연도·학기별 수강 인원 및 AI 추세 요약

**목적:** 특정 과목의 수강 규모와 변화 추세를 빠르게 파악한다.

요구사항:

1. 과목 상세에서 연도·학기별 수강 인원을 표와 차트로 제공한다.
2. 동일 교과목 코드를 우선 사용하고, 코드 변경·과목명 변경 이력을 연결할 수 있어야 한다.
3. AI는 증가·감소·변동 추세를 요약하되 원인으로 단정하지 않는다.
4. 분반 합산 여부, 집계 기준, 데이터 출처, 마지막 갱신일을 표시한다.
5. 수강 인원을 확보하지 못한 학기는 `데이터 없음`으로 표시하고 추정값과 혼합하지 않는다.

완료 조건:

- 사용자가 과목별 학기 추세와 실제 원자료 수치를 함께 확인할 수 있다.
- AI 요약의 모든 숫자가 화면의 집계값과 일치한다.

### F7. 학과별 AI 역량 커리큘럼 및 학년별 활동 추천

**목적:** 학과 특성에 맞춰 AI 활용 역량을 단계적으로 개발한다.

요구사항:

1. 학과, 적용 교육과정 연도, 현재 학년, 관심 분야, 이수 과목을 입력받는다.
2. 학년별로 추천 과목, 프로젝트, 동아리·공모전·연구·인턴 활동, 결과물을 제안한다.
3. 검색창에 관심 키워드를 입력하면 관련 역량, 추천 과목, 선수과목, 활동을 다시 구성한다.
4. 각 추천에 `추천 이유`, `기대 역량`, `선행 지식`, `근거 출처`, `확신 수준`을 표시한다.
5. 사용자가 항목을 추가·삭제·순서 변경한 뒤 수정본을 저장할 수 있어야 한다.
6. 학과 필수 요건과 진로 추천 항목을 시각적으로 구분한다.
7. 공식 데이터가 아닌 AI 제안에는 명확히 `AI 제안` 배지를 표시한다.

### F8. 포트폴리오 빌더

**목적:** 커리큘럼에서 계획한 활동을 실제 포트폴리오 결과물로 연결한다.

요구사항:

1. 커리큘럼과 나란히 보거나 즉시 이동할 수 있는 포트폴리오 화면을 제공한다.
2. 과목·프로젝트·자격증·대외활동별로 목표, 기간, 역할, 사용 기술, 결과, 링크, 회고를 기록한다.
3. 커리큘럼 항목을 포트폴리오 계획으로 가져올 수 있어야 한다.
4. 학년별 목표와 완료율을 표시한다.
5. 외부 공개는 기본 비공개로 하며 사용자가 명시적으로 공개 범위를 선택한다.

### F9. 자격증 추천 및 교육 공지 연계

**목적:** 관심 분야에 필요한 자격증과 교내 지원 기회를 연결한다.

요구사항:

1. 분야·직무 검색 결과에 관련 자격증, 발급 기관, 유효기간 여부, 시험 공식 링크를 제공한다.
2. `필수`, `우대`, `학습 목적 추천`을 근거 없이 단정하지 않고 출처에 따라 구분한다.
3. 학교 공지에 자격증 교육·응시료 지원 공지가 올라오면 해당 자격증 화면과 연결한다.
4. 만료되었거나 접수 기간이 지난 공지는 상태를 명확히 표시한다.

### F10. 시간표 기반 수업 허브

**목적:** 학기 시간표를 학습 및 취업 준비의 중심 화면으로 사용한다.

요구사항:

1. 사용자가 만든 연도·학기별 시간표를 저장하고 다시 열 수 있어야 한다.
2. 각 수업에 사용자가 강의계획, 주차별 메모, 과제·시험 정보를 입력하거나 수정할 수 있다.
3. AI가 입력된 자료를 기반으로 수업 목표, 핵심 주제, 학습 계획을 요약한다.
4. 사용자는 AI 요약을 직접 수정하고, 원본 AI 요약으로 되돌릴 수 있다.
5. 수업과 관심 직무를 연결해 개념·프로젝트·경험 기반 면접 질문을 생성한다.
6. 면접 질문에는 질문 의도와 답변에 활용할 수 있는 수업 근거를 함께 제공한다.
7. 자료가 없는 경우 과목명만으로 구체적 수업 내용을 지어내지 않고 추가 입력을 요청한다.

### F11. 교재 기반 학습 가이드

**목적:** 수업 교재를 실제 학습 계획과 신뢰 가능한 참고자료로 연결한다.

요구사항:

1. 사용자가 교재명, 저자, 판본, 목차 또는 강의계획 정보를 입력한다.
2. AI가 주차별 학습 순서, 선행 개념, 복습 방식, 연습 계획을 제안한다.
3. 참고 사이트는 공식 문서, 공개 강의, 도서관·학교 구독 자원 등을 우선 제시한다.
4. 사이트명, 링크, 추천 이유, 무료·유료 여부를 표시한다.
5. 교재 원문을 저장·재현하지 않고 저작권 범위 내 요약과 학습 안내만 제공한다.

### F12. 학과별 이수체계도 및 선수과목 검증

**목적:** 추천 결과가 실제 교육과정 규칙을 준수하도록 한다.

요구사항:

1. 학과·학번 또는 교육과정 적용 연도별 이수체계도를 제공한다.
2. 과목 간 선수·후수·동시수강 관계와 최소 학년 또는 이수 조건을 구조화한다.
3. 커리큘럼 및 시간표 생성 시 미충족 선수과목을 자동 탐지한다.
4. 충돌 시 추천을 막거나 경고하고, 해결 가능한 선행 이수 경로를 제안한다.
5. 복수전공·부전공·편입·교육과정 개정 예외를 지원할 수 있는 데이터 구조를 갖춘다.
6. 졸업 요건 판단에는 `참고용이며 학과 확인 필요` 안내와 공식 출처를 제공한다.

### F13. 통합 공지·취업 정보 및 키워드 알림

**목적:** 흩어진 기회를 한곳에서 탐색하고 놓치지 않게 한다.

요구사항:

1. 학교 공지, 학과 공지, 취업 공고를 출처별로 수집·분류한다.
2. 홈에서 최근 공지 N개를 보여주며 N은 사용자 설정 또는 제품 기본값으로 관리한다.
3. 사용자는 `어학연수`, `반도체`, `장학금` 등 관심 키워드를 저장할 수 있다.
4. 제목뿐 아니라 본문과 첨부파일의 추출 가능한 텍스트를 검색 대상으로 삼는다.
5. 신규 공지가 키워드와 일치하면 인앱 알림을 보내고, 이메일·푸시는 별도 동의 후 제공한다.
6. 중복 공지, 수정 공지, 마감일 변경을 식별하고 알림 과다를 방지한다.
7. 알림에서 일치한 키워드와 문장을 강조하고 원문 링크로 이동시킨다.
8. 취업 공고는 직무, 기업, 근무지, 마감일, 요구 역량으로 필터링한다.

### F14. 선배 취업 자료 및 성공 후기

**목적:** 학교가 공개를 허용한 실제 사례를 진로 준비에 활용한다.

요구사항:

1. 학교 취업성공후기는 원문 링크, 출처, 게시일, 직무·산업 태그와 함께 제공한다.
2. 자기소개서는 학교의 공개 범위, 이용약관, 저작권, 개인정보 및 재배포 허용 여부를 먼저 확인한다.
3. 허용되지 않은 경우 원문을 복제하지 않고 공식 페이지 링크와 검색 기능만 제공한다.
4. 개인정보가 포함된 자료는 별도 동의와 비식별화 정책 없이는 수집하지 않는다.
5. AI는 여러 사례의 공통 준비 전략을 요약할 수 있지만 문장을 그대로 재사용하도록 유도하지 않는다.

### F15. 선호 시간 기반 시간표 자동 생성

**목적:** 사용자의 생활 패턴과 필수 이수 조건을 함께 만족하는 시간표 후보를 만든다.

요구사항:

1. 오전 선호, 오후 선호, 특정 요일 공강, 제외 시간, 최소·최대 학점을 입력받는다.
2. 전공필수 등 반드시 포함할 과목은 선호 시간보다 우선 배치한다.
3. 필수 과목 간 충돌 시 임의로 누락하지 않고 충돌과 대안을 보여준다.
4. 강의 시간 중복, 선수과목, 개설 학기, 수강 대상 제한을 검증한다.
5. 여러 후보를 공강, 이동시간, 선호 충족률, 총 학점 기준으로 비교한다.
6. 기존 F5의 캠퍼스 이동시간 검증과 연동한다.

## 8. AI 설명 가능성과 사용자 통제

모든 AI 생성 결과는 다음 원칙을 공통 적용한다.

- AI 결과와 공식 사실을 시각적으로 구분한다.
- 추천마다 사용한 입력, 규칙, 공식 출처, 생성 시각을 확인할 수 있게 한다.
- `왜 이 결과가 나왔나요?` 영역에 추천 근거와 제외된 대안을 간단히 설명한다.
- 사용자가 결과를 수정·재생성·피드백할 수 있게 한다.
- 사실을 확인할 자료가 부족하면 추정하지 않고 부족한 정보를 밝힌다.
- 중요한 규칙은 AI가 아니라 결정론적 검증 로직으로 재검사한다.

## 9. 데이터 요구사항

| 데이터 | 핵심 필드 | 권장 출처 | 갱신 주기 |
| --- | --- | --- | --- |
| 과목 개설 | 과목 코드, 분반, 학기, 시간, 장소, 담당 학과 | 공식 수강편람 | 학기별 및 정정 시 |
| 수강 인원 | 과목·분반·연도·학기, 인원, 집계 기준 | 학교 제공 자료 | 학기별 |
| 교육과정 | 학과, 적용 연도, 필수·선택 학점, 이수 구분 | 학과 교육과정·수강편람 | 개정 시 |
| 선수과목 | 선행·후속 과목 코드, 조건, 예외, 적용 연도 | 학과 공식 자료 | 개정 시 |
| 이수체계도 | 단계, 권장 학년·학기, 과목 관계 | 학과 공식 자료 | 개정 시 |

## 10. 데이터 수집 및 운영 정책

1. 공식 API·공개 데이터·학교가 제공한 파일을 우선 사용한다.
2. 웹 수집 전 robots 정책, 이용약관, 인증 요구, 저작권과 개인정보 처리 근거를 확인한다.
3. 원문 전체 저장이 불필요한 경우 메타데이터와 원문 링크만 보관한다.
4. 수집 실패, 파서 오류, 출처 변경, 오래된 데이터를 관리자 화면에서 확인할 수 있어야 한다.
5. 운영자가 AI 분류, 공지 중복, 선수과목 관계, 이수체계도 버전을 검수·수정할 수 있어야 한다.
6. 사용자에게 영향을 준 데이터 변경은 감사 로그를 남긴다.

## 11. 알림 정책

- 키워드별 알림 활성화와 채널을 사용자가 선택한다.
- 기본값은 인앱 알림이며 이메일·푸시는 별도 수신 동의를 받는다.
- 동일 공지의 단순 수정으로 반복 알림하지 않는다. 마감일 등 핵심 정보 변경은 예외로 한다.
- 키워드가 너무 넓어 알림이 많을 경우 빈도와 구체화 방법을 안내한다.
- 알림에서 키워드 삭제, 일시정지, 출처 차단을 바로 수행할 수 있게 한다.

## 12. 개인정보·보안·저작권

- 학번, 이수 내역, 관심 진로, 시간표와 포트폴리오는 개인정보로 취급한다.
- 최소 수집, 목적 제한, 보관 기간, 삭제 기능을 명시한다.
- 포트폴리오와 시간표는 기본 비공개로 설정한다.
- 자기소개서·후기에는 작성자 동의, 공개 범위, 2차 이용 가능 여부를 기록한다.
- AI 학습에 사용자 자료를 별도로 활용하려면 명시적 동의를 받는다.
- 관리자 수정, 데이터 내보내기, 삭제 작업은 감사 로그를 남긴다.

## 15. 오픈 이슈

개발 착수 전에 다음 항목의 담당자와 결론이 필요하다.

1. 첫 출시 대상 학과와 적용 교육과정 연도는 어디까지인가?
2. 연도·학기별 실제 수강 인원 데이터를 학교에서 제공받을 수 있는가?
3. 공식 선수과목 데이터가 별도 표로 존재하는가, 이수체계도에서 추출해야 하는가?
4. 학교·학과 공지 수집과 알림 재가공이 이용약관상 허용되는가?
5. 취업 공고는 학교 취업지원 시스템만 다룰지 외부 채용 플랫폼도 포함할지 결정해야 한다.
6. 선배 자기소개서와 취업성공후기의 공개·재사용 권한을 누가 승인하는가?
7. 알림 채널의 MVP를 인앱으로 한정할 것인가?
8. 포트폴리오의 외부 공유·PDF 내보내기를 초기 범위에 포함할 것인가?
9. 만족도 조사 결과를 추천 모델 개선에 어떤 방식으로 반영할 것인가?

## 16. 출시 승인 기준

- 대상 학과의 공식 이수체계도와 선수과목이 운영자 검수를 통과한다.
- 추천 결과가 필수 과목, 선수과목, 시간 충돌 규칙을 위반하지 않는다.
- AI 추천 이유와 출처가 사용자 화면에 표시된다.
- 사용자가 AI 결과를 수정하고 저장할 수 있다.
- 공지 원문 링크, 게시일, 마감일, 마지막 확인 시각이 표시된다.
- 알림 동의·해제·키워드 삭제가 정상 동작한다.
- 개인정보 삭제와 포트폴리오 비공개 기본값이 검증된다.
- 저작권·개인정보 검토가 끝나지 않은 자기소개서 원문은 노출되지 않는다.
