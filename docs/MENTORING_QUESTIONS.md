# 멘토링 질문 리스트 (2026-08-11 회의 기반)

> 이 문서는 2026-08-11 팀 회의에서 나온 아이디어/필요사항 메모를 정리하고, 그 중 우리끼리는 판단하기 어렵거나
> 멘토(지도교수/멘토)의 조언이 필요한 지점을 질문 형태로 추린 것이다. **PRD(`docs/PRD.md`)는 아직 고치지
> 않았다** — 멘토링에서 방향이 정해지면 그때 `docs/SPRINT_PLAN.md`의 오픈 이슈 로그에 결정을 기록하고,
> 필요 시 PRD에 반영한다(13장 관리자 기능처럼 명시적 요청이 있을 때만 PRD를 직접 수정하는 기존 원칙 유지).

## 1. 원본 회의 메모

**추가 아이디어**
1. 년도/학기 기준으로 몇 명이 해당 과목을 들었는지 AI로 요약
2. 학과별 AI 활용 역량 강화 흐름: 커리큘럼 생성 화면 → 포트폴리오 제작 창(학년별 추천 활동) → 검색 키워드로
   관련 커리큘럼 안내 → 해당 분야 필요 자격증 안내 → 학교 공지 중 자격증 교육 공지 알림 → 사용자가 등록한
   키워드(예: "어학연수")가 포함된 공지 발생 시 알림
3. 학기별로 짠 시간표를 AI가 요약 + 사용자가 수정 가능 → 수업 관련 예상 면접 질문 생성
4. 수업에 필요한 교재를 바탕으로 공부법·참고 사이트 요약
5. 학과별 이수체계도(커리큘럼 로드맵) 상시 노출
6. 취업 공고 안내
7. 학교/학과 공지사항 노출(최근 n개)
8. (가능하면) 학교 사이트의 선배 자기소개서 수집
9. 학교 취업성공후기 수집
10. 오전/오후/공강 선호를 선택하면 자동으로 시간표 생성(전공필수 등 필수 요소는 선호와 무관하게 강제 배치)

**필요 사항**
1. 선수과목 정보 필요
2. 커리큘럼 등 신뢰도 확보 필요 — 만족도 조사 진행 / 커뮤니티 의견 수렴 / 커리큘럼 아래에 AI가 "왜 이런
   결과가 나왔는지" 요약 제공

## 2. 멘토링에서 물어볼 질문

### 2.1 범위·우선순위
- 위 10개 아이디어를 전부 이번 학기(또는 남은 스프린트) 안에 다루는 건 비현실적으로 보인다. 멘토가 보기에
  **핵심 차별화 기능은 어느 것**이고, 나머지는 "있으면 좋은" 수준으로 미뤄도 되는가?
- F1~F5(리뷰/검색/산업분야/커리큘럼/시간표)가 이미 구현된 상태에서, 이번 아이디어들은 "F4/F5의 확장"인지
  "완전히 새로운 F6(취업/포트폴리오)"로 분리해서 관리하는 게 나은지 — 기능 분류 기준에 대한 의견을 듣고 싶다.

### 2.2 외부 데이터 수집의 적법성 (자소서 / 취업성공후기 / 학교 공지)
- 학교 사이트에 게시된 **선배 자소서·취업성공후기를 크롤링/수집**하는 것이 저작권·개인정보 측면에서
  문제가 없는지 — 학교 측에 사전 협의나 별도 동의 절차가 필요한 사안인지 멘토의 의견을 구하고 싶다.
  (수집·가공한 텍스트를 AI 학습/요약에 활용하는 것까지 포함해서.)
- 자소서·후기 게시물에 작성자 개인정보(이름, 학번 등)가 노출돼 있을 가능성이 있는데, 이를 앱에 그대로
  노출해도 되는지 아니면 반드시 익명화/발췌 요약만 해야 하는지.
- 학교/학과 공지사항을 정기적으로 가져오는 것(크롤링 vs 학교 제공 RSS/API 유무)이 학교 정책상 허용되는
  방식인지 — 학교 측에 공식 데이터 제공을 요청할 창구가 있는지도 궁금하다.

### 2.3 키워드 알림 기능의 인프라 부담
- "특정 키워드 등록 → 해당 키워드가 포함된 공지 발생 시 알림"은 **주기적 크롤링/폴링 + 알림 발송(이메일 or
  푸시) 인프라**가 새로 필요하다. 이미 SMTP 기반 이메일 발송(`lib/auth/mailer.ts`)은 있지만 실시간/주기적
  배치 작업은 없는 상태다 — 이 정도 인프라 투자가 프로젝트 평가 기준에서 가치 있다고 보는지, 아니면 더
  단순한 형태(예: 로그인 시 최신 공지 n개 노출)로 축소해도 되는지 의견을 듣고 싶다.

### 2.4 선수과목·이수체계도 데이터
- `curricula.prerequisiteCodes`는 현재 전자공학부·컴퓨터인공지능학부 두 학과만, 그것도 **더미(예시) 데이터**로
  채워져 있다(`lib/db/scripts/seed-curricula.ts` 참고 — 공식 선수과목 관계는 학교 어디서도 공개되어 있지
  않음을 이미 확인함). 학교 측에서 **공식 선수과목 데이터나 학과별 이수체계도 원본**을 받을 수 있는 경로가
  있는지, 없다면 "참고용" 표시를 유지한 채 AI 추정으로 대체하는 현재 방향이 괜찮은지 확인하고 싶다.
- 이수체계도를 "상시 노출"하려면 학과별 원본 이미지/표가 필요한데, 지금 확보된 자료(수강편람 PDF)에
  이수체계도 자체는 없다 — 별도로 학과 사무실에 요청해야 하는 자료인지?

### 2.5 커리큘럼 신뢰도 확보 방안
- "만족도 조사"와 "커뮤니티 의견 제시"를 신뢰도 보강 수단으로 제안했는데, 이는 사실상 **리뷰 시스템(F1)을
  커리큘럼 추천에도 붙이는 것**과 유사하다. 커리큘럼별 평가를 리뷰처럼 누적하는 게 맞는 방향인지, 별도의
  가벼운 피드백(👍/👎 정도)으로 충분한지 의견이 필요하다.
- "AI가 왜 이런 커리큘럼이 나왔는지 요약"은 이미 F4에 일부 있다(`lib/ai/curriculum-reasons.ts` — 선정된
  선택과목에 대한 사유 텍스트). 여기서 원하는 건 그보다 더 상세한 **근거 설명(추천 알고리즘의 설명가능성)**
  인지, 현재 수준의 사유 텍스트로 충분한지 구체화가 필요하다.

### 2.6 AI 면접 질문 생성 / 교재 기반 학습법 추천
- 강의계획서 원문이 없어 F2/F3도 과목명 기반으로만 태깅하고 있다는 제약이 이미 있다(CLAUDE.md 참고). "수업
  관련 예상 면접 질문"이나 "교재 기반 공부법 추천"도 결국 **과목명(+수강생이 남긴 리뷰 텍스트) 정도의
  빈약한 입력**으로 AI가 생성해야 하는데, 이 정도 정보량으로 만든 결과물의 신뢰성을 어느 수준까지 사용자에게
  제시해도 되는지(참고용 disclaimer 필요 여부 등) 확인하고 싶다.
- "교재"는 어디서 가져오나? 수강편람에도 지정 교재 정보는 없다 — 학교 측에 교재 정보를 받을 방법이
  있는지, 없다면 이 기능 자체를 보류해야 하는지.

### 2.7 시간표 자동 생성(오전/오후/공강 선호)
- F5 "내 시간표"는 현재 사용자가 과목을 수동으로 담는 장바구니(`cart_items`) 방식이다. "선호 시간대 선택 →
  자동 시간표 생성"은 **제약 충족 스케줄링 문제**(전공필수 고정 배치 + 선호 시간대 최대 충족 + 시간 중복
  회피)로, 기존 F4의 그리디/AI 설계 방식과는 다른 종류의 알고리즘이 필요하다 — 이번 범위에 포함할 정도로
  우선순위가 높은지, 아니면 다음 학기 과제로 넘겨도 되는지 의견을 구하고 싶다.

### 2.8 수강 인원 요약(년도/학기별 몇 명 들었는지)
- `courses.enrolledCount`(수강인원)는 이미 스키마에 있다 — 이 항목은 AI 요약이 아니라 **단순 집계 표시**로도
  충분할 것 같은데, 굳이 AI를 거쳐야 하는 이유(예: 여러 학기 추이를 자연어로 설명)가 있는지, 아니면
  차트/표로 바로 보여주는 게 더 나은지 확인하고 싶다.

## 3. 정리되면 반영할 곳
- 멘토링 결과로 우선순위/범위가 확정되면 `docs/SPRINT_PLAN.md`의 다음 스프린트 항목과 오픈 이슈 로그에
  기록한다.
- PRD에 새 기능(F6 등)으로 편입하기로 결정되면, 13장(관리자 기능) 사례처럼 사용자 승인 하에 PRD를 직접
  수정한다.
