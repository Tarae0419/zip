> 이 문서는 기존 구현을 완료로 승계하지 않는다. 화면이나 코드가 이미 있어도 PRD2의 데이터 신뢰성, 계정 저장,

## 1. 계획 목표

- 과목 탐색부터 학사 규칙, 커리큘럼, 시간표, 수업 기록, 포트폴리오, 자격증·취업 기회까지 하나의 검증 가능한 흐름으로 연결한다.
- 기존 기능을 폐기하지 않고 재사용 가능한 부분은 유지하되, 시제품·브라우저 저장·혼합 데이터 구조는 점진적으로 교체한다.
- 공식 사실, 규칙 판정, 학생 입력, AI 제안을 데이터와 UI에서 분리한다.
- 이미 구현된 기능도 현행 기준선 측정 → 문제 재현 → 재설계·최적화 → 회귀 검증 순서로 다시 완료한다.
- 외부 데이터나 이용 권한이 확인되지 않은 기능은 AI 추정으로 채우지 않고 데이터 준비 중 상태를 제공한다.

## 2. 재기준선 원칙

### 2.1 구현 존재는 완료가 아니다

기존 계획의 완료 체크는 구현 이력으로만 참고한다. 이 계획의 모든 항목은 미완료 상태에서 시작하고 다음 상태로 관리한다.

| 상태 | 의미 |
| --- | --- |
| 대기 | 아직 시작하지 않음 |
| 진행 중 | 스프린트 목표와 담당자가 확정되어 작업 중 |
| 외부 의존 | 승인·공식 데이터·공급자 키가 필요하며 기술 작업과 분리해 추적 |
| 검증 중 | 구현은 있으나 수용 조건 또는 회귀 검증이 남음 |
| PRD2 완료 | 공통 완료 기준과 기능별 수용 조건을 모두 통과 |

작업 라벨은 다음과 같다.

- [재설계]: 동작·데이터 흐름·책임 경계를 다시 정의하는 작업
- [최적화]: 측정된 성능·비용·접근성·사용성 문제를 개선하는 작업
- [마이그레이션]: 기존 DB 또는 localStorage 데이터를 새 구조로 안전하게 이전하는 작업
- [신규]: 현재 코드에 없는 기능을 추가하는 작업
- [검증/권한]: 공식 출처, 이용 조건, 실제 데이터 품질을 확인하는 작업
- [운영]: 관리자 검수, 실패 대응, 지표·감사 이력을 만드는 작업
- [품질]: 테스트·정적 검사·회귀·관측 도구를 복구하거나 보강하는 작업

### 2.2 스프린트 운영 규칙

- 한 스프린트에는 사용자에게 검증 가능한 세로 기능 조각 하나만 확정 목표로 둔다.
- 범위가 한 주에 들어오지 않으면 R4-A, R4-B처럼 나누고 수용 조건을 줄여서 완료 처리하지 않는다.
- 스프린트 용량의 기본 배분은 기능·재설계 60%, 기존 기능 최적화 20%, 테스트·관측·문서 20%로 한다.
- 외부 승인은 구현 완료 조건과 분리한다. 승인 여부와 대체 경로를 확정하면 검증 작업은 끝낼 수 있지만 제품 기능은 승인 전까지 완료로 표시하지 않는다.
- 각 스프린트 시작 시 현재 응답 시간, DB 쿼리 수, AI 호출 수·비용, 오류 상태, 접근성 문제를 측정하고 종료 시 전후 값을 기록한다.
- 프로덕션 배포는 자동 완료 조건이 아니다. 로컬 마이그레이션 검증, 테스트, 타입 검사, 린트, Next.js 빌드까지를 기본 게이트로 둔다.

## 4. 릴리스 게이트와 의존성

| 게이트 | 통과 조건 | 차단하는 범위 |
| --- | --- | --- |
| G0 데이터·권한 | 대상 학과·입학연도와 각 출처가 사용 가능/승인 대기/사용 불가로 분류됨 | 공식 학사 규칙, 공지, 자격증, 학습 자료, 취업 사례 |
| G1 보안·저장 | 회전 가능한 서버 세션, 계정 소유권, 마이그레이션·롤백 경로가 검증됨 | 개인 계획·기록·포트폴리오·피드백 서버 저장 |
| G2 학사 규칙 | F12 구조화 규칙과 공통 검증 서비스가 공식 표본으로 검수됨 | F4 확정, F7 과목 계획, F15 확정 시간표 |
| G3 시간표 계약 | F15 확정 시간표·수업 순서·건물 ID 계약이 안정화됨 | F5 실제 이동 경로, F10 수업 허브 |
| G4 외부 콘텐츠 | 출처별 수집·요약·재사용·철회 범위가 문서화됨 | F9·F11·F13·F14 |

핵심 의존 순서는 F12 → F4 → F7/F15, F15 → F5/F10, F7/F10 → F8, F13 → F9이다.
PRD2가 F5를 최우선으로 지정한 것과 F15 의존성을 함께 만족시키기 위해 R0에서 TMAP 실호출과 좌표 품질을 먼저 검증하고,
제품 통합은 F15 계약이 안정된 뒤 R7에서 완료한다.

## 6. 스프린트별 백로그와 종료 조건

### R0 — 재기준선·Phase 0·TMAP 타당성

목표: 기존 완료 표시를 PRD2 기준으로 재평가하고 외부 의존성과 측정 기준을 확정한다.

- [ ] [재설계] F1~F16의 사용자 여정, 데이터 흐름, 서버 액션, 관리자 경로를 구현 존재/재검증/재설계/미지원으로 분류한다.
- [ ] [검증/권한] 대상 학과·입학연도와 학사·수강 인원·공지·채용·자격증·교재·취업 사례 출처를 확정한다.
- [ ] [검증/권한] 출처마다 담당자, 허용 근거, 적용 기간, 갱신 주기, 검수 상태, 중단 조건을 기록한다.
- [x] [검증/권한] TMAP 상품·appKey·현재 약관·쿼터를 확인하고 대표 10구간의 구조화 경로 응답을 검증한다.
- [ ] [검증/권한] 대표 10구간의 실제 출입구와 보행로 스냅 품질을 현장에서 수동 검수한다.
- [ ] [최적화] 주요 페이지 응답 시간, DB 쿼리, 클라이언트 번들, AI 호출·실패, 지도 요청의 기준선을 기록한다.

종료 조건: 같은 키워드가 과목 순위와 활동에 모두 추적 가능하게 반영되고, 각 결과에서 공식 사실·규칙·AI 제안과 버전을 확인할 수 있다.

### R9 — F16 추천 품질 폐쇄 루프

목표: 브라우저 만족도를 데이터·추천 개선으로 이어지는 운영 흐름으로 바꾼다.

- [ ] [마이그레이션] 기존 3항목 만족도를 정확성·유용성·설명 가능성·최신성 4항목의 계정 저장으로 교체한다.
- [ ] [재설계] 평가를 대상 엔티티, 데이터 버전, 추천 버전, 모델·프롬프트 버전에 연결한다.
- [ ] [신규] 비공개 정정 제안과 접수·검토 중·반영·반려 상태, 근거 URL, 처리 이유를 제공한다.
- [ ] [신규] 공개 학생 의견은 대상 버전 연결, 사전 검수, 신고·숨김·삭제·이의제기 정책이 준비된 범위에서만 연다.
- [ ] [운영] 관리자가 학과·기능·버전·유형별 반복 이슈와 만족도 분포를 집계한다.
- [ ] [재설계] 추천 재생성 시 과거 평가를 새 버전에 승계하지 않고 학생 의견과 공식 확인 정보를 구분한다.

종료 조건: 평가와 정정이 정확한 버전에 연결되고 사용자가 처리 결과를 확인할 수 있다. 공개 의견은 운영 담당자와 정책이 없으면 기능 플래그로 닫혀 있어야 한다.

### R10 — F6 검증형 수강 추세와 과목 상세 최적화

목표: 수강 인원 숫자와 AI 문장을 원본에서 재현하고 과목 상세의 의사결정 근거를 통합한다.

- [ ] [마이그레이션] 학기·분반별 EnrollmentSnapshot과 정원·수강 인원·원본 레코드·측정 시각을 저장한다.
- [ ] [재설계] 결측 분반, 비공개, 수집 실패, 폐강, 실제 0명을 서로 다른 상태로 계산·표시한다.
- [ ] [신규] 운영자가 승인한 과목 코드 변경 계보와 교차개설·팀티칭 중복 방지 규칙을 적용한다.
- [ ] [신규] 학기별 합계·정원·충원율·분반 수·전 학기·전년 동기 증감을 코드로 계산한다.
- [ ] [재설계] AI에는 구조화 통계만 주고 출력 숫자를 서버에서 검증하며 실패 시 규칙 문장으로 대체한다.
- [ ] [최적화] 과목 상세에서 F1 수강평·F6 추세·F12 선수 정보의 병렬 조회, 캐시, 로딩·빈 상태를 재측정한다.
- [ ] [검증] 원본 표본 합계, 한 학기 단정 금지, 부분 분반 경고, 출처·집계 기준·갱신일을 테스트한다.

종료 조건: 표본 집계가 원본과 일치하고 결측과 0이 구분되며, AI 문장의 숫자 일치율 100%와 출처 표시율 100%를 달성한다.

### R11 — F10 계정형 수업 허브

목표: 브라우저 메모 시제품을 비공개·복원 가능한 학습 기록과 면접 근거로 바꾼다.

- [ ] [마이그레이션] study-hub localStorage를 계정·학기·시간표 항목별 StudyRecord로 한 번만 가져온다.
- [ ] [재설계] 강의계획서, 학생 입력, AI 원본, 사용자 수정본과 생성 입력 버전을 분리한다.
- [ ] [재설계] 요약과 면접 질문의 각 80자 근거를 서버에서 정규화·계산하고 면접 질문은 사용자 입력 근거가 있을 때만 생성한다.
- [ ] [검증] 질문별 근거가 실제 입력에 존재하는지 확인하고 입력에 없는 성과·기술·역할을 차단한다.
- [ ] [신규] 원본 복원, 30일 휴지통, 즉시 영구 삭제, 계정 내보내기와 기본 비공개를 제공한다.
- [ ] [신규] 선택한 기록을 원본 ID와 버전이 포함된 계약으로 F8에 전달한다.
- [ ] [최적화] 입력 중 전체 localStorage 직렬화를 없애고 저장 충돌·AI 실패에도 작성 내용을 보존한다.

종료 조건: 시간표·수업 기록 연결, 80자 게이트, 원본·수정본 복원, 질문 근거, 소유권·삭제 테스트가 모두 통과한다.

### R12 — F8 계정형 포트폴리오

목표: 커리큘럼·수업 활동을 다기기에서 복원 가능한 비공개 성과 기록으로 전환한다.

- [ ] [마이그레이션] portfolio localStorage를 계정 저장으로 가져오고 원본 ID+계획/수업 버전으로 중복을 방지한다.
- [ ] [신규] 데스크톱 커리큘럼 병렬 작업창, 모바일 탭, 독립 편집 화면이 같은 데이터를 사용한다.
- [ ] [재설계] 항목에 목표·기간·역할·기술·과정·결과·수치·링크·회고·원본 상태를 분리한다.
- [ ] [신규] 낙관적 동시성으로 여러 기기 충돌을 감지하고 30일 휴지통·복원·영구 삭제를 제공한다.
- [ ] [신규] 비공개 메모·증빙 포함 여부를 확인한 뒤 PDF와 구조화 데이터로 내보낸다.
- [ ] [검증/권한] 증빙 저장은 허용 형식·용량·악성 파일 검사·저장 위치가 결정된 경우에만 연다.
- [ ] [최적화] 매 키 입력 전체 배열 직렬화를 제거하고 긴 목록·모바일·키보드 편집을 개선한다.
- [ ] [검증] AI 표현 개선이 사용자가 입력하지 않은 수치·역할·성과를 추가하지 않는지 검증한다.

종료 조건: 중복 없는 가져오기, 다기기 복원·충돌 감지, 기본 비공개, 휴지통, 검토 가능한 내보내기가 동작한다.

### R13 — F13 공지 수집·최근 N개

목표: 허용된 학교·학과 출처를 멱등하게 수집하고 접근 범위와 갱신 상태를 신뢰할 수 있게 만든다.

- [ ] [검증/권한] 표준 Department와 허용된 department-source map을 확정하고 임의 URL 조합을 금지한다.
- [ ] [신규] ContentSource, Notice, NoticeVersion, NoticeAttachment 메타데이터와 수집 실행 이력을 추가한다.
- [ ] [신규] 전북대 본부와 승인된 K2Web 출처의 목록·상세 파서 및 수동 notices sync 명령을 만든다.
- [ ] [재설계] 외부 ID와 내용 해시로 중복·수정·재게시 후보를 구분하고 조회수·수집 시각은 변경 판정에서 제외한다.
- [ ] [재설계] 비로그인은 본부 공지, 로그인은 서버의 표준 학과 키와 일치하는 공지만 추가 조회한다.
- [ ] [신규] 최근 5~50개, 전체·내 학과·모아보기·유형·기간 필터와 실패·지연·미연결 상태를 제공한다.
- [ ] [운영] 403·429·CAPTCHA·로그인 요구 시 우회하지 않고 중단하며 마지막 성공·실패·건수 급감을 관리자에게 표시한다.
- [ ] [검증] HTML fixture, 반복 동기화 멱등성, 수정 감지, A학과 사용자의 B학과 접근 차단을 테스트한다.

종료 조건: 같은 입력을 반복해도 중복이 없고, 공개/학과 접근 경계와 실패 상태가 검증되며 첨부는 이름과 공식 링크만 저장한다.

### R14 — F13 키워드 알림·취업 공고와 F9 자격증

목표: 사용자의 관심 신호를 근거가 보이는 인앱 기회 알림으로 연결한다.

- [ ] [신규] 키워드·동의어 구독, 일시중지·해제, NoticeMatch, Notification의 버전별 중복 방지를 구현한다.
- [ ] [신규] 제목·본문 일치 문구와 새 글·중요 수정·마감 변경을 구분해 인앱 알림으로 제공한다.
- [ ] [신규] 기업·직무·지역·고용형태·역량·마감·공식 지원 URL을 가진 취업 공고 원장을 추가한다.
- [ ] [신규] 자격명·기관·공식 URL·분야·응시 조건·유효기간·검증일을 가진 자격증 원장을 추가한다.
- [ ] [재설계] 필수·우대는 공식 또는 실제 채용 근거가 있을 때만 표시하고 약한 근거는 탐색 권장으로 낮춘다.
- [ ] [재설계] F3 관심 분야와 F7 역량을 공통 신호로 재사용하되 사용자가 이유와 출처를 확인하게 한다.
- [ ] [신규] 자격증의 교육·응시료 지원 공지와 만료·폐지·명칭 변경 상태를 연결한다.
- [ ] [운영] 관련 없음 피드백, 과도하게 일반적인 키워드 경고, 구독 해제와 알림 정밀도를 집계한다.

종료 조건: 같은 공지 버전·키워드 알림 중복 0건, 구독 해제 즉시 반영, 공식 출처 없는 필수·우대 표현 0건, 키워드 정밀도 90% 이상이다.

### R15 — 통합 하드닝·릴리스 판정

목표: 기능별 구현이 아니라 핵심 사용자 여정 전체가 PRD2 성공 기준을 만족하는지 판정한다.

- [ ] [검증] 검색 → 커리큘럼 → 시간표 → 이동 경로 → 수업 기록 → 포트폴리오 핵심 E2E를 자동화한다.
- [ ] [검증] 비로그인 공지 → 로그인 학과 공지 → 키워드 알림 → 자격증·취업 기회 E2E를 자동화한다.
- [ ] [검증] 계정 소유권, 관리자 권한, 세션 만료·폐기, 삭제·복원·내보내기, AI 전송 범위를 보안 회귀 테스트한다.
- [ ] [최적화] R0 대비 페이지·쿼리·번들·AI·지도 비용을 비교하고 근거 없이 악화된 항목은 릴리스하지 않는다.
- [ ] [최적화] 모바일, 키보드, 포커스, 스크린리더, reduced motion, 긴 텍스트·빈·오래됨·실패 상태를 전 화면에서 재검증한다.
- [ ] [검증] 마이그레이션, 백필, 롤백, 백업·복구, 외부 수집 중단, AI·지도 공급자 실패 훈련을 수행한다.
- [ ] [운영] 성공 지표 대시보드와 오류·정정·수집·비용 담당자 및 대응 절차를 확정한다.
- [ ] [품질] 단위·통합·E2E, 타입 검사, ESLint, 로컬 Next.js 빌드를 모두 통과한다.

종료 조건: 프로젝트 완료 기준을 모두 만족하고, 미완료 P2·외부 의존 기능은 노출·문구·데이터 준비 중 상태가 명확하다.

### R16 — 조건부 F11 교재 학습 가이드

진입 조건: 허용 자료 원장, 링크 검증 경로, 강의계획서·교재 정보 사용 범위가 G4를 통과한다.

- [ ] [신규] 제목·저자·판본·ISBN·출판사·과목·학기·출처를 구분한 교재 원장을 만든다.
- [ ] [신규] 허용된 공식 문서·도서관·공개 강의의 URL·비용·인증·확인일을 관리한다.
- [ ] [재설계] 판본을 확인할 수 없으면 장 번호를 단정하지 않고 강의계획서와 사용자 입력을 구분한다.
- [ ] [신규] 수정 가능한 예습·수업·복습·연습 계획을 F10 주차 기록으로 보낸다.
- [ ] [검증] 존재하지 않는 URL, 긴 원문·문제 재현, 허용되지 않은 사이트 추천을 차단한다.

종료 조건: 모든 URL과 판본·비용 상태가 검증되고 저작권 원문을 복제하지 않으며 수정 계획이 수업 허브에 연결된다.

### R17 — 조건부 F14 취업 사례·허용 자료

진입 조건: 콘텐츠별 재사용 권한 증빙, 비식별화 담당자, 철회·삭제 절차가 G4를 통과한다.

- [ ] [신규] 학과·직무·산업·활동·과목·게시일·원문 URL을 가진 취업 사례 색인을 만든다.
- [ ] [재설계] 링크만, 요약, 발췌, 원문, 사용 불가 권한 상태에 따라 제공 범위를 자동 분기한다.
- [ ] [검증] 이름·학번·연락처·기업 내부정보와 소수 집단 재식별 위험을 공개 전에 검수한다.
- [ ] [운영] 권리자 삭제·범위 변경 시 캐시·색인·파생 요약을 함께 비활성화하고 처리 이력을 남긴다.
- [ ] [검증] 허가 없는 자기소개서 원문 저장·재배포·긴 유사 요약이 발생하지 않는지 테스트한다.

종료 조건: 모든 사례에 출처·권한 상태가 있고 비식별화·철회가 동작한다. 권한을 확보하지 못하면 링크도 임의 수집하지 않는다.

| F4 커리큘럼 | R5 | R8, R15 | 규칙 우선, 계정 버전, 복원, 하드 위반 0 |
| F5 시간표·지도 | R6, R7 | R11, R15 | 필수 우선 후보, 서버 재검증, 실제 경로·폴백 |
| 로그인·회원가입 | R1 | R15 | 회전 세션, OTP 제한, 소유권·권한 |
| 관리자 | R1, R2, R4, R9, R13 | R15 | 최소 권한, 출처·규칙·피드백·수집 운영 |
| F6·F7·F8·F10·F12·F15·F16 시제품 | 각 기능 스프린트 | R15 | localStorage 제거, 공식 출처, 버전·복원·삭제·테스트 |

어떤 행도 주 재작업과 후속 회귀를 모두 통과하기 전에는 PRD2 완료로 변경하지 않는다.

## 8. 공통 완료 기준

모든 스프린트와 기능은 다음을 함께 만족해야 한다.

### 기능·데이터

- [ ] 수용 조건이 PRD2 요구사항과 자동 또는 재현 가능한 수동 테스트로 연결되어 있다.
- [ ] 공식 사실, 규칙 판정, 학생 입력, AI 제안이 데이터와 UI에서 구분된다.
- [ ] 출처, 적용 기간, 갱신일, 검수 상태가 필요한 모든 정보에 표시된다.
- [ ] 데이터 없음, 실제 0, 오래됨, 비공개, 수집·외부·AI 실패가 정상 상태와 구분된다.
- [ ] 기존 데이터의 백필 건수·해시·중복·누락을 검증하고 롤백할 수 있다.

### AI·추천

- [ ] AI는 허용 후보 안의 순위·설명·요약만 맡고 학사 하드 판정과 숫자 계산을 하지 않는다.
- [ ] 허용 ID, 숫자, 날짜, URL을 서버에서 검증하고 실패 시 안전한 규칙 결과 또는 생성 실패를 제공한다.
- [ ] 모델·프롬프트·입력 해시·근거 ID·생성 시각·검증 상태와 사용자 수정본이 분리 저장된다.
- [ ] 사용자 수정본을 재생성이 덮어쓰지 않는다.

### 보안·개인정보·권한

- [ ] 모든 사용자 데이터 쿼리와 서버 액션이 계정 소유권을 검증한다.
- [ ] 개인 산출물은 기본 비공개이며 삭제·복원·영구 삭제·내보내기 정책을 따른다.
- [ ] AI 전송 범위와 외부 콘텐츠 이용 범위가 허용된 데이터로 제한된다.
- [ ] 관리자 변경과 콘텐츠 철회·정정 처리에 감사 이력이 있다.

### 품질·최적화

- [ ] 변경 전 기준선과 변경 후 응답 시간·DB 쿼리·번들·AI/외부 호출·오류율을 기록한다.
- [ ] 선택한 병목은 개선되거나, 개선하지 못한 이유와 후속 백로그가 승인되어 있다.
- [ ] 단위, 통합, 핵심 E2E, 권한, 마이그레이션·롤백 테스트를 위험에 비례해 추가한다.
- [ ] 타입 검사, ESLint, 로컬 Next.js 빌드가 통과한다.
- [ ] 모바일, 키보드, 포커스, 스크린리더, reduced motion, 긴 텍스트·빈 상태 QA를 통과한다.
- [ ] 관련 PRD 수용 조건, 운영 문서, 스프린트 상태가 함께 갱신된다.
